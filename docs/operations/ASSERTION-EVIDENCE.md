# Assertion evidence behind test runners

Recovery plans may assign the assertion role to a span in an already bound source
file, as well as to an executed check entrypoint. A shell runner can invoke a Python
or JavaScript test module; the actual assertion remains in that module. Requiring
a citation to the runner incorrectly rejects reviews that cite the real tests.

Source-path confinement, hashes, span bounds, complete gate coverage and semantic
assertion/oracle review remain required. Naming a source file as an assertion does
not automatically establish that it is a valid test. No reference is invented and
no failed receipt is revised. No provider, ledger or budget behavior changes.

Validation: 11 synthetic recovery tests passed, including a shell runner invoking
an assertion module and refusal of an unbound assertion path before an allowance.
Independent review approved. Live recovery and installed-runtime activation remain
unverified; this change grants no new allowance.
