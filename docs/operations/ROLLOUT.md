# Separate rollout proposal

## Boundary

The operation implementation and its acceptance fixtures use isolated repositories,
synthetic transports, synthetic identities and a local Git publication remote.
They do not certify live model accuracy, confidence calibration, cost savings,
installed-browser behavior or end-to-end delivery. No retained real ticket is
restarted, no real allowance is granted, and no installed runtime is changed.
The Community dependency stack must be reviewed and integrated before a CX port.

## Proposed live validation (not executed)

1. Select the exact integrated Community commit and verify its test receipts.
   Inspect the installation inventory in a temporary installation. Record the
   current installed revision without modifying it.
2. Prepare a public synthetic repository with a small specification, explicit
   architecture/rules, meaningful positive and negative tests, and one manual
   case. Review the operation plan and source scope. Use no retained private ticket
   contents or private configuration in published evidence.
3. Resolve the configured author and independent reviewer routes. Verify a pinned
   Jev deployment if compact obligations are selected. Record capabilities,
   authentication mode and concrete requested models; reject unavailable routes.
4. Present the exact repository/worktree, artifact binding, recipe, operator,
   per-operation and aggregate limits for explicit live authorization. No existing
   exhausted allowance is reset. Stop on unknown invocation or unchanged failure.
5. Exercise individual operations and the equivalent recipe with negative controls.
   Compare raw outputs, test outcomes, dependency invalidation, reservations and
   manual acceptance. Record request bytes, calls, cache hits, abstentions,
   disagreements, parallel execution totals and wall elapsed. Review false
   approvals/rejections on a labeled corpus before interpreting thresholds.
6. Connect the browser to the temporary synthetic dashboard. Inspect admission,
   findings, evidence, authorization and restart; compare the same CLI responses.
   Keep installed-browser validation a separate receipt.
7. Only after explicit installation authorization, install the reviewed revision
   and verify runtime identity. Preserve the prior runtime and retained state.
   Present a new assessment and bounded proposal for any real-ticket adoption.

Production deployment, merge and real-ticket continuation are outside this
proposal. This document authorizes none of them.
