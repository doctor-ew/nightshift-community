# Nightshift 0.4.0 release candidate

## Changes

- Task-first control-room dashboard with six selectable stages, recorded provider/model, stage-bound evidence and retained attempt history. Existing admission and authorization rules remain intact.
- Smaller request intake with expandable scope/tests/limits and runtime diagnostics; missing choices open automatically.
- Retained spec approval, continuation and proof/accounting fixes from the integration branch.
- Two themed presentation decks with executable rehearsal instructions and the real self-hosted build/review/repair story.

## Evidence and limits

PRs #132, #136, #137 and #140 contain the integration history. Issue #138 records a genuine self-hosted run: independent Review caught a continuation-control accessibility regression; its repair passed re-review and Drift. QA automation passed, but its original stage failed on a required human visual case. The operator subsequently explicitly requested merge. No original receipt or budget was rewritten to pass. Issue #139 tracks the human-acceptance code-repair loop and remains a known limitation.

The run's default 3,600 active-second allowance sums tracked invocation durations, including overlapping stage and role invocations. It is not elapsed wall time, model compute time or billed cost. The 64-reservation ceiling was not exhausted. No new model allowance is granted by this release.

## Production boundary

Merging the version change to main is a production release action: after successful main push CI, the existing release workflow tags that verified revision v0.4.0. Stable public installations can then select it. Publishing this release does not switch an installation configured to use the private source/channel. Preserve private settings and the pinned rehearsal unless the operator explicitly chooses a separate installation change.
